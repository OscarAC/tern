:::meta description: How Tern turns names into HTML elements, and the shape of a note's output: the allowlists, reserved names, the output contract, titles and labels, table captions, figures, numbering, references, ids, raw HTML, safe rendering and metadata. ::: ::site-nav # Elements and output {#top} ::toc This page is about what a note becomes. The syntax pages say how to write a container, a leaf or a reference; this one says which HTML element each name produces, what classes and attributes tern adds, how titles, labels, numbers and reference texts are made, how ids are given out, where raw HTML may enter, and what `:::meta` does to the page's head. Most of what follows depends on the **vocabulary** a note declares. The core declares none: without a schema entry, a name gets the plain output described in [the fallback](#step-fallback), with no label, no number and no table of contents. Labels, counters and the `::toc` filler come from a schema, declared by an add-on or by `window.TERN.schema` in the head ([Vocabulary and behaviour](schema.html#schema)). So that you can see the difference, many examples below come in pairs: the same source rendered with no schema, which is what a plain note gets, and rendered with the **demo schema**. The demo schema is the vocabulary the conformance corpus uses: `theorem`, `lemma`, `proposition` and `corollary` on one counter, `definition`, `example` and `exercise` on their own, `proof` with an end mark, the callouts `note`, `tip`, `important`, `warning` and `caution`, `recall` as a `
`, counted `figure`, `table` and `code` (listings), and a `toc` leaf. It is defined in docs.js and listed in full on the [Vocabulary page](schema.html#demo-schema). An example that uses it says so above its source. ## How a name becomes an element {#names} Three constructs carry a name: a container (`:::NAME`), a leaf (`::NAME`) and an inline element (`:NAME[…]`). Each becomes one HTML element. Which element is decided by the name, the level it is used at, an optional `tag=` key and the schema. ```tern {.live} :::aside[Aside] A container. ::: ::video{src=tide.mp4 controls} Press :kbd[Ctrl] and :idea[an unknown name]. ``` ### Case {#case} Names are case-sensitive. The schema lookup, the allowlists, the reserved list and the custom-element rule all compare names exactly, and every list is lower-case. So `:::Aside` is not the `aside` element but an unknown name, `:KBD[x]` is not `kbd`, and `:::Script` is not the reserved `script`. ```tern {.live} :::Aside Press :KBD[x]. ::: ``` ```tern {.live} :::Script if (a < b) run(); ::: ``` The second example is an ordinary container whose body is parsed as Tern; only the lower-case `:::script` is reserved ([below](#reserved)). The same holds under a schema: `:::Theorem` does not find the demo schema's `theorem`. ```tern {.live schema=demo} :::Theorem Body. ::: ``` ### The five steps {#steps} **Reserved names** are checked first, before anything else ([Reserved names](#reserved)). Then the first of these steps that applies wins: | Step | The element is | Example | Result | |---|---|---|---| | 1 | the `tag=` key's value, when it is in the level's allowlist | `:::box{tag=aside}` | `

` | Whatever the element, the name stays in two places: as a class (unless it is reserved) and as `data-t="NAME"`. That is what CSS and behaviours key on ([What to key on](#keying)). ### Step 1: `tag=` {#step-tag} `tag=` asks for a specific element. It is one of the reserved attribute keys: tern consumes it and never emits it. :::syntax ```tern :::NAME{tag=ELEMENT} ::NAME{tag=ELEMENT} :NAME[content]{tag=ELEMENT} ``` ::: ```tern {.live} :::box{tag=aside} Aside text. ::: Press :key[Esc]{tag=kbd}. ``` - The value must be in the allowlist of the level the name is used at ([The allowlists](#allowlists)). A value outside it gets [`tag.not-allowed`](diagnostics.html#tag-not-allowed) (W) at the `tag` key, and resolution goes on with step 2. - A reserved value, such as `tag=main`, gets [`name.reserved`](diagnostics.html#name-reserved) (W) at the key instead, and resolution goes on with step 2 likewise. - A custom-element name is in no allowlist, so `tag=` cannot name one: write the custom element as the name itself (step 3). - `tag=` beats the schema's `tag`, and beats the custom-element rule. - `tag=` works only on a named element: `:::name`, `::name` or `:name[…]`, including through an attribute line before a container or a leaf, which merges into it. Anywhere else (a bare span, a link, an image, a code span, a heading, a fence, display math, a paragraph through its attribute line) it gets `tag.not-allowed` (W) at the key and is dropped. To choose an element there, use a named one: `:kbd[…]` instead of `[…]{tag=kbd}`. - On a reserved name or a core block (`:::main{tag=section}`, `:::macros{tag=div}`), `tag=` gets [`attr.malformed`](diagnostics.html#attr-malformed) (W) at the key and is dropped: those names keep their own output. ```tern {.live expect="tag.not-allowed"} :::box{tag=span} A container cannot be a span. ::: ``` ```tern {.live expect="name.reserved"} :::box{tag=main} main is never produced. ::: ``` ```tern {.live expect="tag.not-allowed"} :::box{tag=tide-panel} tag= cannot name a custom element. ::: ``` ```tern {.live} :::tide-panel{tag=section} tag= wins over the custom-element rule. ::: ``` ```tern {.live expect="tag.not-allowed tag.not-allowed"} [Esc]{tag=kbd} and [a link](https://example.com){tag=b} {tag=aside} :::box An attribute line merges into the container, so this works. ::: ``` ```tern {.live expect="name.reserved attr.malformed attr.malformed"} :::main{tag=section} A reserved name keeps its fallback. ::: :::macros{tag=div} \gdef\R{\mathbb{R}} ::: ``` With a schema, `tag=` overrides the schema's element, and the schema still supplies the label and the counter. A refused `tag=` falls through to the schema's own `tag`: ```tern {.live schema=demo} :::theorem{tag=article} An article, still Theorem 1. ::: ``` ```tern {.live schema=demo expect="tag.not-allowed"} :::theorem{tag=span} Still a section: the schema's tag decides. ::: ``` ### Step 2: the schema's `tag` {#step-schema} A schema entry may name the element its name becomes. In the demo schema, `theorem` has `tag: 'section'`, a counter and a label, so a theorem is a `
` with a counted label. Without a schema, the same source is just an unknown name. ```tern {.live schema=demo} :::theorem[Rank–nullity] If $V$ is finite-dimensional. ::: ``` ```tern {.live} :::theorem[Rank–nullity] If $V$ is finite-dimensional. ::: ``` The schema's `tag` goes through the same checks as `tag=`, reported at the element's name, since the schema has no position in the note: - a `tag` outside the level's allowlist gets `tag.not-allowed` (W); - a reserved `tag`, such as `tag: 'main'`, gets `name.reserved` (W); - either way, resolution goes on with step 3. For example, with this vocabulary in the head: ```html ``` `:::pull` is a `div.pull`, with `tag.not-allowed` at `pull`, and `:::lead` is a `div.lead`, with `name.reserved` at `lead`. How to declare vocabulary is on the [Vocabulary page](schema.html#fields). ### Step 3: custom elements {#step-custom} A name that is a valid custom-element name becomes that element, at every level. That is how web components get into a note without raw HTML. ```tern {.live} :::tide-panel[Leith]{station=leith} High water at 06:40. ::: ::tide-clock{station=leith units=m} Now :tide-chip[3 m] above datum. ``` A valid custom-element name, as HTML defines it: - starts with a lower-case ASCII letter (`a`–`z`); - contains a hyphen; - has no upper-case ASCII letter; - is not one of the eight hyphenated names HTML reserves: `annotation-xml`, `color-profile`, `font-face`, `font-face-src`, `font-face-uri`, `font-face-format`, `font-face-name` and `missing-glyph`. ```tern {.live} :::font-face A reserved HTML name: a div. ::: :::Tide-Panel Upper case: a div. ::: ``` Names that start with `t-` have the shape of a custom element, but they are reserved, and the reserved check comes first: `:::t-box` is never `` ([Reserved names](#reserved)). ### Step 4: the allowlists {#step-allowlist} A name that is in the allowlist of its level becomes that element. The lists are on [their own section](#allowlists). The same name can map differently per level: `details` is an element as a container and as a leaf, and a `span` inline. ```tern {.live} :::details[More] Hidden. ::: ::details[Leaf content] A :details[span] here. ``` ### Step 5: the fallback {#step-fallback} Any other name becomes a `div` (container, leaf) or a `span` (inline), with the name as its class. Nothing is lost: the content, the attributes and the name are all there. ```tern {.live} :::idea[Key idea]{#k} Body. ::: ::callout[Read *me*] An :aside[inline] one. ``` `:aside` is a `span`: `aside` is a flow element, and the inline allowlist has only phrasing elements. **`name.unknown`.** Only this fallback can be reported, and only when the schema asks for it with `strict: true`. Then a step-5 name gets [`name.unknown`](diagnostics.html#name-unknown) (I) at the name, when it has no schema entry. Known names stay silent: a name the schema declares (even an entry with no `tag`, which is a `div` or `span` too), an allowlisted name and a custom-element name. Turn strict mode on in any of these places: - `strict: true` in the note's own vocabulary, `window.TERN = {schema: {strict: true, …}}` in the head ([`window.TERN`](schema.html#window-tern)). It works in the browser and in the command line, and the note wins: `strict: false` there turns off what an add-on turned on; - `tern.schema.strict = true` in an add-on; - `strict: true` in the `schema` option of the [JavaScript API](api.html#tohtml). ```tern :::idea Body. ::: See :zz[y]. ``` With `strict: true`, this gets `name.unknown` at `idea` (line 1) and at `zz` (line 5). Without it, the same note is silent. ### Empty titles {#empty-title}

An empty `[]` is no title. Without a label, the container has no title element; with one, the title element holds the label alone.

```tern {.live}
:::box[]
No title element.
:::
```

```tern {.live schema=demo}
:::note[]
The label alone.
:::
```

A titled fence follows the same rule: ```` ```js[] ```` is not a listing, just a fence.

### End marks {#end-marks}

A schema entry's `end` is a trailing mark in real text, such as the demo schema's `∎` on `proof`. It is a `span.t-end` with `aria-hidden="true"`, the container's last child. In a figure it comes just before the `figcaption`, since HTML allows a figure's caption only first or last. A merged `:::table` has none, since HTML allows no `span` between table sections. End marks are for containers only.

```tern {.live schema=demo}
:::proof
Trivial.
:::
```

```tern {.live schema=demo}
:::proof[Sketch]{tag=figure}
Body.
:::
```

## Table captions {#table-caption}

A pipe table cannot carry a title or a number. Wrap it in `:::table[Caption]` and the two merge into one `` with a `
`.

:::syntax
```tern
:::table[Caption]{#id .class}
| … | … |
|---|---|
| … | … |
:::
```
:::

```tern {.live schema=demo}
:::table[Phases and exit criteria]{#tbl-phases .wide}
| Phase | Exit |
|---|---|
| P0 | every rule has a case |
:::

See @tbl-phases.
```

Without a schema it merges just the same, with a caption and no label or number:

```tern {.live}
:::table[Phases and exit criteria]{#tbl-phases .wide}
| Phase | Exit |
|---|---|
| P0 | every rule has a case |
:::
```

The rules:

- **When.** A container whose element is `table`, by its name or by `tag=table`, merges when its body is exactly one pipe table. Blank lines around the table do not count.
- **Attributes** are combined, and the container's win: its `#id` beats the table's (silently), and classes accumulate with the container's last. Any other key the container sets beats the table's.
- **The title** becomes ``, first child. Without a written title and without a label, there is no caption.
- **The counter** comes from the schema (`Table` in the demo schema), with or without an id.
- **No end mark**: a schema `end` is left out of a merged table.

```tern {.live schema=demo}
:::table[Order]{#tbl-outer .c-outer}
{#tbl-inner .c-inner}
| a |
|---|
| 1 |
:::
```

```tern {.live}
:::grid[Results]{tag=table}
| a |
|---|
| 1 |
:::
```

**When it does not merge.** A `:::table` whose body is anything else (prose, two tables, cells, a raw ``) is a `div`, with [`table.body`](diagnostics.html#table-body) (W) at the name. The fallback keeps its label and counter, so it still takes a table number.

```tern {.live schema=demo expect="table.body"}
:::table[Prose]
Just prose.
:::

:::table[Real]{#tbl-real}
| a |
|---|
| 1 |
:::

See @tbl-real.
```

A raw `
` inside `:::table` is never merged: raw HTML stays verbatim, and carries its own `
` if it wants one.

```tern {.live expect="table.body"}
:::table[Raw]



1



:::
```

`::table` (a leaf) and `:table[…]` (inline) are not tables: `table` is not in their allowlists.

## Figures {#figures}

A figure is an element whose tag is `figure`: a caption last, and in the demo schema a counted label, "Figure 1". There are two ways to make one.

### Explicit figures {#explicit-figures}

`:::figure[Caption]{#id}` takes any body.

```tern {.live schema=demo}
:::figure[Two ospreys]{#fig-pair}
Ospreys at dawn.
:::
```

When the body is a single paragraph holding only one image, the `` is emitted without a `
`. A body of two image paragraphs keeps both.

```tern {.live schema=demo}
:::figure[An osprey]{#fig-o}
![Osprey](osprey.jpg)
:::
```

```tern {.live schema=demo}
:::figure[Before and after]
![Before](a.jpg)

![After](b.jpg)
:::
```

### Implicit figures {#implicit-figures}

An image alone in its paragraph, with an id, is a figure. No container needed:

```tern {.live schema=demo}
![Osprey, 06:40.](osprey.jpg){#fig-osprey width=70% alt="An osprey in flight"}

See @fig-osprey.
```

A paragraph becomes an implicit figure when **all** of these hold:

- its only content is one image, with its attributes;
- the image carries an `#id`, or an [attribute line](syntax-blocks.html#attribute-line) before the paragraph does;
- it has no ancestor whose tag is `figure`.

Such a paragraph becomes **the same node** as `:::figure[bracket text]{#id}`: the same tag, classes, `data-t`, title slot and counter, so `@fig-osprey` reads "Figure 1". Then:

- the bracket text is the caption, as inline content;
- the `#id` goes to the figure, and so do the attribute line's attributes;
- the image's other attributes stay on ``;
- the image's `alt` is the `alt=` attribute when one is given, and empty otherwise.

**Why the alt is empty.** The caption already describes the image. If the alt repeated it, a screen reader would read the same words twice. Give `alt=` when the image needs a description of its own.

```tern {.live schema=demo}
![The *kernel* of $T$](kernel.svg){#fig-ker .round width=50%}
```

The implicit figure is part of the core, not of the schema: without a schema it is still a `figure`, from the allowlist, with its caption and no label.

```tern {.live}
![Osprey](osprey.jpg){#fig-o}
```

**No id, no figure.** An image without an id, on it or on an attribute line, is always just an image in its paragraph:

```tern {.live schema=demo}
![Osprey](osprey.jpg)

![Osprey](osprey.jpg){.wide}
```

**Attribute lines.** An attribute line with an `#id` makes the figure, as if the image carried it; its other attributes go to the figure, after `t-block figure`. An attribute line with only classes does not make a figure: it goes to the `
`. When both the image and the line have an id, the image's id wins and the line's is dropped.

```tern {.live schema=demo}
{#fig-a .wide}
![A](a.jpg)

{.wide}
![B](b.jpg)
```

**Not a figure.** An image with text, two images, an image inside a link or a table cell, and anything inside a figure stay images:

```tern {.live schema=demo}
![Osprey](osprey.jpg){#img-o} at dawn.

![A](a.jpg){#img-a} ![B](b.jpg){#img-b}
```

```tern {.live schema=demo}
:::figure[Pair]{#fig-p}
:::box
![A](a.jpg){#img-a}
:::
:::
```

"Inside a figure" means any ancestor whose tag is `figure`, whatever its name. Here the image keeps its id and its alt, and the box keeps its `
` because the box's own tag is not `figure`.

An implicit figure can stand in a list item, a quote or a footnote, like any paragraph:

```tern {.live schema=demo}
- ![Nest](nest.jpg){#fig-nest}
```

### Images without a `
` {#figure-images}

Both kinds follow one rule: an element whose tag is `figure`, and whose body is a single paragraph holding only an image, emits the `` without a `
`. It goes by the tag, not the name, so `:::gallery{tag=figure}` follows it too. A paragraph that carries attributes from an attribute line keeps its `
`, to hold them.

```tern {.live}
:::gallery{tag=figure}
![A](a.jpg)
:::

:::figure
{.framed}
![B](b.jpg)
:::
```

## Numbering {#numbering}

The `numbering` transform numbers elements in document order. An outer block is numbered at its opener, before the blocks inside it, and a reference before its target still gets the target's number.

**Counters come from the schema.** An entry's `counter` names a sequence, and names that share a counter share one sequence. In the demo schema, `theorem`, `lemma`, `proposition` and `corollary` share `theorem`; `definition`, `example` and `exercise` have their own; `figure`, `table` and `code` (listings) count separately.

```tern {.live schema=demo}
:::theorem
A.
:::

:::lemma
B.
:::

:::definition
C.
:::

:::corollary
D.
:::
```

```tern {.live schema=demo}
:::theorem
:::lemma
Inner.
:::
Outer.
:::

:::corollary
After.
:::
```

Without a schema nothing is counted: there are no counters to count on. Equations and footnotes are the exception, below.

```tern {.live}
:::theorem
A.
:::

:::lemma
B.
:::
```

A label with no number, such as the demo schema's `proof`, takes no number from any counter. A counter with no label numbers the element and shows the bare number.

**Equations** are numbered only when they have an id, on the counter `equation`, in document order. Their number is `(n)`, in a `span.t-eqno`. Inline math is never numbered. Equations are counted with or without a schema.

```tern {.live}
$$ a $$

$$ b $$ {#eq-b}

$$
c
$$ {#eq-c}

See @eq-c.
```

**Listings** are titled fences, on the schema's `code` entry: "Listing 1" in the demo schema. An untitled fence takes no number; a titled one is numbered with or without an id.

````tern {.live schema=demo}
```js[First]
a();
```

```js
b();
```

```js[Second]{#lst-2}
c();
```

See @lst-2.
````

**Footnotes** are numbered by first reference, not by where their definitions stand, with or without a schema ([footnotes](syntax-blocks.html#footnote-definition)).

```tern {.live}
Later[^b] and sooner[^a].

[^a]: Defined first.
[^b]: Referenced first.
```

**`within`.** A schema entry may set `within: 'h2'`, meant to restart its counter at each level-2 heading. The engine accepts the field and keeps it in the registry, but does not apply it: numbering is document-wide, and no counter restarts.

Elements inside a dropped duplicate footnote definition take no number: that content counts for nothing.

## References {#references}

`@id` is a link to the element with that id, whose text the engine fills from the target ([the reference syntax](syntax-inline.html#reference)). The `refs` transform writes it as ``.

### The default text {#default-ref-text}

| Target | Default text | Example |
|---|---|---|
| a counted element | its label and number, or the schema's `ref` template | `Theorem 1` |
| an equation | `(n)` | `(1)` |
| a heading | its inline content | `The map T` |
| a titled element that is not counted | its title | `Hot surface` |
| a labelled element that is neither counted nor titled | its label | `Proof` |
| anything else | the id | `term` |

```tern {.live schema=demo}
:::theorem[Rank–nullity]{#thm}
:::

$$ E = mc^2 $$ {#eq}

## The *map* $T$ {#map}

:::warning[Hot surface]{#hot}
:::

:::proof{#pf}
:::

A [key term]{#term}.

- @thm, @eq, @map
- @hot, @pf, @term
```

A counted target reads as its label and number even when it has a title. Without a schema the same targets read differently: nothing is counted or labelled, so a titled container reads as its title, and an untitled one as its id.

```tern {.live}
:::theorem[Rank–nullity]{#thm}
:::

:::proof{#pf}
:::

See @thm and @pf.
```

**Templates.** A schema entry's `ref` is a template over `{label}`, `{n}`, `{title}` and `{id}`; the demo schema's theorems use `'{label} {n}'`. `{label}` is the label word ("Theorem"), not the label with its number. When the target lacks a part the template names, such as `{title}` on an untitled block, the default text by kind is used instead. A schema can define a citation style this way: `tern.leaf('bib', {counter: 'bib', ref: '[{n}]'})` makes `@knuth`, on a `::bib{#knuth}`, read `[1]`. The fields are on the [schema page](schema.html#fields).

### Choosing the text: `ref=` {#ref-select}

`ref=` on a reference chooses which part of the target to show.

:::syntax
```tern
@id{ref=label}
@id{ref=number}
@id{ref=title}
@id{ref=full}
```
:::

| Value | Text | Example |
|---|---|---|
| `label` | the label, with its number when counted | `Theorem 1` |
| `number` | the number alone | `1` |
| `title` | the title (a heading's content) | `Rank–nullity` |
| `full` | the label, then the title in parentheses | `Theorem 1 (Rank–nullity)` |

```tern {.live schema=demo}
:::theorem[Rank–nullity]{#thm-rn}
:::

$$ x $$ {#eq-x}

- @thm-rn{ref=label}
- @thm-rn{ref=number}
- @thm-rn{ref=title}
- @thm-rn{ref=full}
- @eq-x{ref=number}
```

- **A part the target lacks** gives the default text, silently: `ref=title` on an untitled theorem, `ref=number` on a heading, `ref=full` on anything without both a label and a title.
- **Any other value** gets [`attr.malformed`](diagnostics.html#attr-malformed) (W) at the value, and the default text.
- `ref=` is consumed: it never reaches the HTML. On anything but a reference it gets `attr.malformed` (W) at the key and is dropped ([Reserved keys out of place](#reserved)).

```tern {.live schema=demo}
:::theorem{#thm-u}
:::

See @thm-u{ref=title}.
```

```tern {.live schema=demo expect="attr.malformed"}
:::theorem[Rank–nullity]{#thm-rn}
:::

See @thm-rn{ref=name}.
```

### Copied text {#copied-text}

The text of a reference is copied from its target, and the copy goes inside a link. So it is flattened, exactly as a [toc entry](#toc-output) is: links are unwrapped to their text, footnote references are left out, and a reference inside it becomes its own target's plain text. A link never nests in a link, and no id is emitted twice. The target itself is untouched.

```tern {.live}
## See [the docs](https://x.org)[^n] and @k {#h}

[t]{#k}

Read @h.

[^n]: A note.
```

Other markup is kept: emphasis, code and math in a heading appear in the reference's text too. Copied markup carries no ids.

### Fragment links {#fragment-links}

For your own text, write an ordinary link to a fragment: `[the test](#lem-inj)`. Tern checks it: a fragment that names no id in the note gets [`ref.dangling`](diagnostics.html#ref-dangling) (W) at the link's `[`, and the link stays a link. A fragment written with non-ASCII letters is percent-encoded in `href` and still checked against the id. A bare `#` is not checked.

```tern {.live expect="ref.dangling"}
## Results

See [the results](#results) and [the proof](#nowhere).
```

### Unresolved references {#unresolved}

An `@name` whose name is no id in the note stays literal text, with `ref.dangling` (W) at the `@` and a hint to write `\@name`. A mention like `@alice` is the usual case.

```tern {.live expect="ref.dangling"}
Ask @alice. Or ask \@bob.
```

## Ids {#ids}

Every id in a note, of every kind, lives in **one registry**: heading ids, container and span ids, equation ids, footnote ids. A reference finds its target there, and the registry keeps the HTML valid by never giving one id to two elements.

### Two passes {#id-passes}

Before anything else, the registry holds **tern's own ids**: `tern-style`, `tern-color-scheme`, `tern-source` and `tern-diagnostics`, which tern.js gives elements of its own in the page (its stylesheet, its colour-scheme meta, the note's source and, on a page `tern build` wrote, the note's diagnostics). Then the `ids` transform fills it in two passes.

1. **Fixed ids**, in document order:
   - every id an author wrote, as `#id` or `id=`: on headings, containers, leaves, inline elements, spans, links, images, code and math spans, titled fences, tables, attribute lines and `$$` closers;
   - every generated footnote id: `fn-LABEL` at the definition, `fnref-LABEL` and `fnref-LABEL-N` at each reference.
2. **Heading slugs**, in document order, for every heading without an id.

So an id you wrote always beats a slug, wherever the two stand: an author who wrote `#kernel` meant it, and a slug is a guess. The slug yields silently.

Tern's own ids come first of all. A heading slug yields to them silently (`## Tern style` gets `tern-style-2`). An id you write that is one of them gets [`id.duplicate`](diagnostics.html#id-duplicate) (W), saying it belongs to tern, and is dropped.

```tern {.live expect="id.duplicate"}
## Tern style

A [span]{#tern-source} keeps no id.
```

```tern {.live schema=demo}
## Kernel

:::definition{#kernel}
The null space.
:::

See @kernel.
```

### Slugs {#slugs}

A heading without an id gets a slug of its plain text: lower-cased, from the first letter on, with runs of other characters turned into `-` ([the heading rules](syntax-blocks.html#heading)). A slug that is already taken, by a fixed id anywhere in the note or by an earlier slug, gets the first free `-2`, `-3`, …, silently. A suffixed slug is an id like any other, so `@notes-2` reaches it.

```tern {.live}
## Notes
## Notes
## Notes

See @notes-2.
```

Fixed ids are registered first, so a slug skips any suffix an author took:

```tern {.live}
## A
## A

See [x]{#a-2}.
```

A reference inside a heading counts as its id in the slug: slugs are made before anything is numbered, so a slug never changes when a target is renumbered. The reference still renders its text.

```tern {.live schema=demo}
:::theorem{#thm-a}
:::

## Proof of @thm-a

See @proof-of-thm-a.
```

### Duplicates {#duplicates}

Two fixed ids that collide get [`id.duplicate`](diagnostics.html#id-duplicate) (W), reported **at both places**: at the first, and at each later one. The first keeps the id; every later element drops its `id` attribute, which keeps the HTML valid. References resolve to the first.

```tern {.live schema=demo expect="id.duplicate id.duplicate"}
:::theorem{#t}
:::

:::lemma{#t}
:::

See @t.
```

The lemma keeps its number, but not the id. The registry spans every kind, so a heading and a span, or an equation and a code span, collide too:

```tern {.live expect="id.duplicate id.duplicate"}
$$ x $$ {#e}

A `c`{#e} span.
```

A heading that loses its own id, as a later duplicate or as an invalid id, gets its slug instead, so every heading keeps an id:

```tern {.live expect="id.duplicate id.duplicate id.invalid"}
:::box{#intro}
:::

## Intro {#intro}
## Setup {id=""}
```

### Invalid and unreferenceable ids {#invalid-ids}

An id can be wrong in two ways, and gets at most one of the two diagnostics:

| Diagnostic | When | The id is |
|---|---|---|
| [`id.invalid`](diagnostics.html#id-invalid) (W) | it is not a valid HTML id: empty, or holding whitespace (`id=""`, `id="a b"`) | dropped |
| [`ref.unreferenceable`](diagnostics.html#ref-unreferenceable) (W) | it is a valid HTML id but `@` cannot reach it: it starts with a digit, or holds `:` or `.` (`id=2024`, `id=a.b`, `id=x:y`) | kept |

Both can only happen through `id=`: `#` takes a name that is always a valid, referenceable id. The diagnostic points at the first letter of `id=`.

```tern {.live expect="id.invalid ref.unreferenceable ref.unreferenceable"}
[a]{id="a b"} [b]{id=2024} [c]{id=v1.2}
```

### Footnote ids {#footnote-ids}

A footnote's ids keep their `fn-` and `fnref-` prefixes, so the label `x` and an id `#x` do not collide. The ids use the definition's label as written, though labels match case-insensitively: `[^Note]` with `[^note]:` gives `fn-note`. A repeated reference gets `fnref-note-2`, `fnref-note-3`, ….

```tern {.live}
One[^Note], two[^note] and [x]{#note}.

[^note]: Text.
```

The generated ids are fixed ids, so `#fn-x` written by hand collides with a footnote `x`. The earlier one in document order keeps the id; a definition that loses it keeps its place in the list, without an `id`.

```tern {.live expect="id.duplicate id.duplicate"}
Text[^x].

[^x]: Note.

See [this]{#fn-x}.
```

Ids inside a dropped duplicate footnote definition are not registered.

## Raw HTML scoping {#raw-html-scoping}

Raw HTML enters a note only through three doors:

- the four raw block kinds: a comment, a raw-text element (`
