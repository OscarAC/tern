Learn these and the rest follows. ### R1: Blocks own their lines {#r1} - A block is recognised from its **first line**. The table start is the only construct that may read one line ahead. - Its end condition is fixed when it opens, and is tested on the current line only. - No block reads another block's state. - List items and footnote definitions do not read ahead across blank lines either: the blank lines are held until the next non-blank line arrives, and that line decides whether they belong to the item. So there are no setext headings: a line of `=` under a paragraph cannot turn the paragraph above into a heading, because that would change a block after the fact. ```tern {.live} Title ===== --- ``` The first three lines are one paragraph, and `---` is a rule. ### R2: Indentation is insignificant {#r2} Indentation means nothing, except in two places: - it decides membership in [list items](#lists) and [footnote definitions](#footnote-definition); - it is removed from the content lines of a [fence](#fence) and the TeX lines of [display math](#display-math), up to the indentation of their opening line. There are no indented code blocks, and container bodies may be indented freely. ```tern {.live} :::aside This is not code: indentation is ignored. # Still a heading ::: ``` ### R3: Trailing whitespace means nothing {#r3} Every line is right-trimmed before Tern looks at it, so editors may trim freely. Two trailing spaces are not a line break; a hard break is a single `\` at the end of the line. ```tern {.live} First line\ second line, after a hard break. ``` Verbatim bodies are the exception: their lines are kept as written (see [Lines and right-trimming](#lines)). ### R4: Two alphabets {#r4} Tern and TeX each have their own marks: | Alphabet | Marks | |---|---| | Tern | `:` `[ ]` `{ }` `@` `#` `|` `>` `*` `~~` `==` `` ` `` `$` | | TeX | `\` `{ }` `^` `_` `&` | - Math (`$…$`, `` $`…` ``, `$$`, `:::macros`) is opaque to Tern: nothing inside it is Tern syntax. - Outside math, `\` followed by a letter is a literal backslash, so `\alpha` and `C:\Users` are text. ```tern {.live} Inside math $\alpha^2$ is TeX; outside, \alpha and C:\Users are text. ``` ### R5: One attribute grammar {#r5} Attributes are always written `{#id .class key=value}`, always in braces, and there is no unbraced form. The same group works in five positions (see [Attributes](#attributes)). ```tern {.live} ## Kernel {#kernel .wide} :::aside{.note-box} A [highlighted]{.hl} word and `code`{.lang-js}. ::: ``` ### R6: Elements are names {#r6} `:::name`, `::name` and `:name[…]` become the element their name denotes, through a level-aware allowlist, the schema, or the custom-element rule. Any other name becomes a `div` or `span` with the name as its class. The full mapping is on [Elements and output](elements.html#names). ```tern {.live} :::aside An `aside` element. ::: :::idea An unknown name: a `div` with the class `idea`. ::: ::video{src=tide.mp4 controls} ``` ### R7: Nothing is lost silently {#r7} Every malformed construct stays visible at its own position and gets a diagnostic with a code, a severity, a message, a position and a hint that quotes the fix. | Severity | Meaning | |---|---| | error | content lost or meaning changed | | warning | probably not what you meant | | info | a hint | ```tern {.live expect="block.opener-junk"} :::aside[Proof] #pf .big The attributes were written without braces. ::: ``` The block still opens, and the junk is shown in an error paragraph. Every code is on the [Diagnostics](diagnostics.html#severity) page. ### R8: One documented spelling per construct {#r8} Each construct has one spelling, and this documentation uses it. A few unambiguous Markdown alternates are accepted, but never used here as the primary form: | Construct | Spelling | Also accepted | |---|---|---| | Thematic break | `---` | `***`, `___`, `- - -`, `* * *` | | Fenced code | ```` ``` ```` | `~~~` | ```tern {.live} *** ~~~js const tilde = true; ~~~ ``` ## Lexical conventions {#lexical} These conventions apply before any construct is recognised. ### Where the note starts {#note-start} A note is an HTML file. The `tern.js` script tag splits it in two: - **The head** is everything before the tag: the lines before it, and anything before the tag on its own line (in the canonical first line, the doctype, ``, `` and ``). It is ordinary HTML that the browser parses before any script runs, and Tern preserves it (see [Metadata](elements.html#metadata)). - **The note** is everything after the line that holds the tag. It is what this page describes. ```html <!doctype html><html lang="en"><meta charset="utf-8"><title>Linear maps # Linear maps The note starts on the line after the `tern.js` tag. ``` - Diagnostic positions count lines from the first line of the note: the head's lines do not count. The browser console adds the file line, and the command line and the editor report file lines. - Which tag counts as "the `tern.js` line" is defined precisely under [Detection](tools.html#detection). How the file is put together is on [Publishing](publishing.html#the-file). ### Normalisation {#normalisation} Before anything else, the whole source is normalised: | In the source | Becomes | |---|---| | `\r\n` (CRLF) | `\n` | | `\r` alone (CR) | `\n` | | a byte-order mark (U+FEFF) at the very start | nothing | | NUL (U+0000) | U+FFFD, the replacement character | - Normalisation covers every line, verbatim bodies included, so a NUL inside a fence is replaced too. - `\r\r\n` is a CR followed by a CRLF: two line breaks. - Positions (line, column, offset) refer to the normalised text, so a CRLF counts as one character. ### Lines and right-trimming {#lines} Each line is right-trimmed (its trailing spaces and tabs removed) before it is classified. The exceptions are the lines fed to a **verbatim body**, which are kept byte for byte: - [fence](#fence) content; - [raw HTML blocks](#raw-html); - [display math](#display-math); - the bodies of [`:::macros`, `:::meta` and `{raw}` containers](#raw-body). A verbatim body's own closer (a closing fence, a `$$` closer, a raw-body closer) is still tested on the right-trimmed line, and it may be indented. ````tern {.live} ``` Leading spaces inside a fence are kept. So is deeper indentation. ``` ```` The closing fence above is indented six spaces and still closes the fence. The last line of a note needs no line break: the end of the note closes whatever is open. A whitespace-only line is blank once trimmed, so it ends a paragraph like an empty line. ### Columns and tabs {#columns} - A tab advances to the next multiple of 4 columns. - Columns matter only for list-item and footnote membership, and for dedenting fence and display-math content. - Everywhere else, leading whitespace is ignored when a line is classified. Here `1. a` puts the item's content at column 5. The next line, two spaces and a tab, reaches only column 4 (the next multiple of 4), so it is outside the item. ```tern {.live} 1. a b ``` With a three-space gap the content column is 4, and the same two spaces and a tab reach it, so `b` belongs to the item. ```tern {.live} 1. a b ``` :::note Tab stops decide membership only. In diagnostic positions a tab is one column, and columns count UTF-16 code units, so a character outside the Basic Multilingual Plane takes two. See [Positions](diagnostics.html#positions). ::: ### Character classes {#character-classes} Names, ids, keys and labels are Unicode. This keeps a run like `{{{{` linear to scan. - **Quotes.** Inside quotes nothing is special and there are no escapes, so `pattern="\d+"` is literal. To put `"` in a value, use single quotes, and the other way round. - **Empty.** `{}`, or a pair of braces holding only spaces, is not a group. - **Inline content.** Code spans and other inline atoms are found before groups are attached, so a backtick inside a glued group pairs as a code span. A `}` or `{` inside quotes does not end or abort the candidate: ```tern {.live} A [span]{title="a } b" data-open='{'} with braces in its values. ``` Quoted values are literal, and the emitted value escapes what HTML needs: ```tern {.live} A [field]{pattern="\d+" title='say "hi"'}. ``` An aborted candidate and an empty group are silent text: ```tern {.live} [x]{.a {b}} and [y]{} stay as written. ``` After a reference, `{}` is still consumed, as a terminator with no attributes. It is how you end a reference that is glued to the text after it, as in Japanese: ```tern {.live} ## Kernel {#kernel} これは@kernel{}です。 ``` :::warning A backtick inside a glued group pairs with a later backtick as a code span, because code spans bind tighter than attribute values. Here the "group" is broken and the code span swallows text. Write ``` in a quoted value instead. ::: ```tern {.live} [x]{title="a`b"} and `c` ``` ### Strong and weak groups {#strong-and-weak} - A group is **strong** if it holds at least one `#id`, `.class` or `key=value`. - A group of bare keys only, such as `{open}`, is **weak**. Weak groups are accepted only where a `{` cannot be mistaken for text: glued after a bracket construct or a reference, and at the end of a structural line. Everywhere else a weak group stays text, silently. ```tern {.live} A [span]{hidden} binds a weak group; `code`{hidden} does not. {open} A weak group alone on a line is just text, and this line continues the paragraph. ``` A single `key=value` makes a group strong, and its bare keys come along: ```tern {.live} {lang=fr translate} Bonjour. ``` ### Merging and emission {#merging-and-emission} **Merging.** Within a group, and between groups that apply to the same element: - Keys are ASCII-lower-cased first, as the browser lower-cases attribute names. `{ID=a CLASS=b}` is `{#a .b}`. - The last `#id` wins. `id=` is the same attribute as `#`. - Classes accumulate in source order. `class=` merges with `.` items, and a quoted `class="a b"` adds two classes. - For any other repeated key, the last value wins. ```tern {.live} {#a .b id=c class="d e" k=1 k=2} Merged. ``` **Emission.** - `id` comes first, then `class`, then the other attributes in source order. A repeated key keeps the place where it first appeared. - In values, `"`, `<` and `&` are escaped; a well-formed character reference such as `&` or `©` is kept as written. - A bare key becomes an HTML boolean attribute: `controls`, not `controls=""`. ```tern {.live} A [span]{b=1 .c a=2 #i b=3 title="© & "}. ``` ### Reserved keys and names {#reserved} **Reserved keys** are consumed by Tern and never emitted: | Key | Where it acts | What it does | |---|---|---| | `tag` | named elements: `:::name`, `::name`, `:name[…]`, when the name is neither reserved nor a core block | overrides the element ([Elements](elements.html#names)) | | `raw` | containers | makes the body verbatim ([Raw-body containers](#raw-body)) | | `cols` | containers, leaves, inline elements (not core blocks such as `:::macros`) | sets the grid ([Cells](#cells)) | | `ref` | references | chooses the reference text ([References](elements.html#references)) | | `lines`, `hl`, `start` | fences only | line numbers and highlighted lines ([Fenced code](#fence-lines)) | **A reserved key where it does not apply** is dropped with a diagnostic at the key, never silently: - `tag=` on anything but a named element (a span, a link, an image, a code span, a heading, a paragraph through an attribute line) gets [`tag.not-allowed`](diagnostics.html#tag-not-allowed) (warning); - `tag=` on a reserved or core name (`:::main{tag=section}`, `:::macros{tag=div}`), `ref=` anywhere but a reference, `raw` anywhere but a container, and `cols=` anywhere but a container, leaf or inline element (or on a core block) get [`attr.malformed`](diagnostics.html#attr-malformed) (warning). ```tern {.live expect="tag.not-allowed tag.not-allowed attr.malformed attr.malformed attr.malformed"} A [span]{tag=b}, a [link](https://example.com){ref=title}, an ![image](tide.jpg){cols=2}. {tag=section raw} A paragraph cannot change its element. ``` `lines`, `hl` and `start` are reserved on fences only; anywhere else they are ordinary attributes: ```tern {.live} :::aside{lines start=3 tag=section} `tag` is consumed and picks the element; `lines` and `start` are emitted. ::: ``` **Reserved names.** Three things would let a note hijack the output contract, so they are dropped with `name.reserved` (warning): - the key `data-t` (in any case: `DATA-T` is lower-cased to it), reported at the key's first letter; - the class `tern`; - any class starting with `t-`, reported at the class's `.`. Class names are case-sensitive, so `.Tern` is an ordinary class. ```tern {.live expect="name.reserved name.reserved name.reserved"} {.tern .t-box .Tern data-t=x} Only `Tern` survives. ``` Diagnostics: [`attr.malformed`](diagnostics.html#attr-malformed), [`name.reserved`](diagnostics.html#name-reserved). ### The five positions {#positions} These are the only places a `{` is special: | Position | Example | Accepts | Binds to | If the candidate does not parse | |---|---|---|---|---| | glued after a bracket construct (link, image, span, inline element) or a reference | `[t](u){.btn}`, `[x]{hidden}`, `:kbd[C]{.big}` | any group | that node | stays text, with `attr.malformed` at the first rejected character. `{}` and an aborted candidate are silent text; after a reference, `{}` is consumed | | glued after a code span, a math span, a `*`, `**`, `~~` or `==` closer, an autolink or a footnote reference | `` `c`{.x} ``, `$x${#e}`, `**b**{.y}` | strong groups only | that node | stays text; `attr.malformed` only when the candidate starts with `#` or `.` | | the end of a structural line: container opener, leaf, fence opener, `$$` closer, `+++` | `:::details[More]{open}`, `$$ {#eq}`, `+++ {.muted}` | any group, glued or after spaces | that block | as each construct says | | the end of a heading line | `## Kernel {#kernel .wide}` | a strong group, glued or after spaces | the heading | stays heading text; `attr.malformed` when it starts with `#` or `.` | | alone on a line | `{#intro .lead}` | one or more strong groups | the next block | the line is a paragraph; `attr.malformed` when it starts with `{#` or `{.` | A group bound to a node is part of that node's source position. #### 1. It keeps a stack of open containers (quotes, list items, footnote definitions, `:::` containers, cells) and at most one open leaf (a paragraph, a table, a fence, a raw HTML block, display math, a raw body, or a pending attribute line). For each line it takes five steps: 1. **Prefixes.** Match the open containers' prefixes, outermost first. What is left is the *remainder*. 2. **Verbatim leaf.** If a verbatim leaf is open, feed it the remainder. 3. **Lazy continuation.** If a prefix failed and a paragraph is open, the line may continue it. 4. **Classification.** Otherwise, classify the remainder by the sixteen rows below; the first row that matches wins. 5. **End of the note.** After the last line, close everything still open. ### Prefixes {#prefixes} Only three containers have a line prefix: | Container | Its prefix matches when | |---|---| | blockquote | after optional leading whitespace comes `>`, then an optional space or tab. A tab is consumed whole | | list item | the line is indented to the item's content column, or is blank | | footnote definition | the line is indented at least 2 columns, or is blank | - `:::` containers and cells have no prefix: they continue on every line until a closer. - The prefix of an inner container is matched after the outer one's, on what the outer one left. - After the matched prefixes, what remains is the *remainder*. Every later step looks only at the remainder. The quote prefix needs only the `>`, so `>b` continues an open quote, although it cannot open one (opening needs a space, a tab or the end of the line after `>`): ```tern {.live} > An open quote >continues on this line. >This line opens nothing. ``` ### Verbatim leaves {#verbatim-leaves} The verbatim leaves are a [fence](#fence), a [raw HTML block](#raw-html), [display math](#display-math) and a [raw-body container](#raw-body). While one is open: - **If every prefix matched**, the remainder goes to the leaf. The leaf first tests its *terminators* (display math and generic raw HTML only have them), then its own end condition; otherwise the line is content. Nothing in it is classified. - **If a prefix failed**, the leaf closes as unclosed, with its diagnostic, together with every container whose prefix failed. So a `#` line inside a fence inside a quote is code, and a quote line that loses its `>` ends the fence: ````tern {.live expect="block.unclosed-fence"} > ``` > # code, not a heading after the quote ```` ### Lazy continuation {#lazy} A line continues the open paragraph *lazily*, without its prefixes, when all of these hold: - a prefix failed; - the innermost open block is a paragraph; - the remainder would be a paragraph line (row 16), or would not start any block. ```tern {.live} > A quote, lazily continued. ``` Laziness reaches through every failed prefix, so here `b` continues the paragraph of the item inside the quote: ```tern {.live} > - a b ``` The "interrupts a paragraph" restrictions of the last column below apply only when every prefix matched. A line that failed a prefix and starts any block starts it. So `2. two` after a quoted line leaves the quote and starts a list at 2: ```tern {.live} > para 2. two ``` The same rule keeps list items siblings: the item's prefix fails on the next marker line, and the marker starts a new item even where it could not interrupt a paragraph (an item numbered 2, an empty item). ```tern {.live} 1. one 2. two * one * * three ``` Laziness needs an open paragraph. After a heading, a fence or display math, a line that fails the prefix ends the container: ```tern {.live} > # A quoted heading not lazy ``` ### Classification: the sixteen rows {#rows} The remainder is classified with its leading whitespace ignored.
