# CommonMark imports

CommonMark 0.31.2 examples (https://spec.commonmark.org/0.31.2/spec.json) for emphasis,
backslash escapes, code spans and the backslash form of hard line breaks, checked against
Tern's documentation rather than CommonMark. A case whose prose says "Differs from CommonMark" expects
Tern's result. Output conventions (heading ids, data-t="code") are Tern's throughout.

Not imported:

- Emphasis 357-365, 371-377, 382-390, 397-403, 406-408, 424-426, 434-435, 448-459,
  461-463, 465, 468-470, 474, 477, 479, 481 (63): they test `_` runs, and `_` is never a
  delimiter. 438 and 441 are imported: their `_` is content.
- Escapes 18: indented code block (indentation is insignificant).
- Escapes 21: a CommonMark type-7 HTML block; `<a` is phrasing and starts a paragraph.
- Escapes 23: reference link definition (there are no reference links).
- Escapes 20, code spans 346: the href of an angle autolink that CommonMark percent-encodes
  (`\` and `` ` ``); link destinations are normalised, but the documentation does not say whether an
  autolink's href is normalised too.
- Hard line breaks 633, 635, 636, 638, 640, 642, 645, 647: the trailing-space form; lines are
  right-trimmed and trailing whitespace means nothing.

Escapes 22 is imported: backslash escapes apply in link destinations and titles.
No HTML-block example (148-191) is imported, so Tern's raw HTML rules (the error block, `html.wrapper`) change nothing here.

``

Differs from CommonMark: the trailing space on line 1 (written `\u0020`) is trimmed, so one space joins `bar` and `baz` where CommonMark has two; the `json ast` block asserts it, since the HTML normaliser folds spaces.

````tern

baz`
````

````html
<p><code>foo   bar baz</code></p>
````
