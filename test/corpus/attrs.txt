# Attributes

The one attribute grammar (finding the group, strong and weak groups, merging and emission, reserved keys and names, the positions) and the attribute line. The bare span `[x]{…}` accepts any group, so it carries most grammar cases; the attribute line accepts strong groups only.

## attrs/line-basic

spec: syntax-blocks#attribute-line syntax-blocks#r5

The attribute-line example: an attribute line attaches its group to the block that starts on the next line.

````tern
{.byline}
Lecture 7 · O. Carrera
````

````html
<p class="byline">Lecture 7 · O. Carrera</p>
````

## attrs/line-before-list

spec: syntax-blocks#attribute-line

An attribute line before a list goes on the list element.

````tern
{.steps}
- one
- two
````

````html
<ul class="steps">
<li>one</li>
<li>two</li>
</ul>
````

## attrs/line-before-heading

spec: syntax-blocks#attribute-line

An attribute line before a heading gives it its id, so no slug is made.

````tern
{#intro .x}
## Start
````

````html
<h2 id="intro" class="x">Start</h2>
````



## attrs/line-before-display-math

spec: syntax-blocks#attribute-line syntax-blocks#display-math

On display math the attributes go on `div.t-eq`; an id there numbers the equation.

````tern

$$
x = 1
$$
````


## attrs/line-before-container-opener-wins

spec: syntax-blocks#attribute-line syntax-blocks#merging-and-emission

An attribute line merges into the container it precedes; where both set the id or a key, the opener's own value wins.

````tern
{#a .x key=1}
:::box{#b key=2}
Text.
:::
````

````html
<div id="b" class="t-block box x" data-t="box" key="2">
<p>Text.</p>
</div>
````

## attrs/line-before-container-classes

spec: syntax-blocks#attribute-line syntax-blocks#merging-and-emission

Classes from the attribute line and from the opener both reach the container, the line's first: "the opener's own attributes win" applies to the id and other keys, never to classes, which accumulate.

````tern
{.x}
:::box{.y}
Text.
:::
````

````html
<div class="t-block box x y" data-t="box">
<p>Text.</p>
</div>
````

````tern

::spacer{#s}
````

````html
<div id="s" class="spacer x" data-t="spacer"></div>
````

## attrs/orphan

spec: syntax-blocks#attribute-line

An attribute line followed by a blank line has nothing to attach to: it is shown as paragraph text, with `attributes.orphan`, and is an `attributes` node in the AST.

````tern
{.lead}

Text.
````

````html
<p>{.lead}</p>
<p>Text.</p>
````

````json ast
{"type": "root", "children": [{"type": "attributes"}, {"type": "paragraph"}]}
````

## attrs/orphan-lines-one-paragraph

spec: syntax-blocks#attribute-line syntax-blocks#line-algorithm

An attribute line interrupts the paragraph above it; when no block follows, consecutive orphan lines form one paragraph of their own, with one `attributes.orphan` at the first line.

````tern

{.a}
{#b}

More.
````

````html
<p>Text.</p>
<p>{.a}
{#b}</p>
<p>More.</p>
````

## attrs/line-malformed-is-text

spec: syntax-blocks#attribute-line syntax-blocks#positions

An unparsable group alone on a line is not an attribute line: it is a paragraph line, and the next line continues the paragraph. A line that starts `{#` or `{.` gets `attr.malformed` at the first character the grammar rejects (the `%`), as a heading's trailing group does.

````tern

Text.
````

````html

Text.</p>
````

## attrs/weak-after-math-is-text

spec: syntax-blocks#positions syntax-blocks#strong-and-weak

After a math span only strong groups bind; a weak one stays text, with no diagnostic because it does not start with `#` or `.`.


## attrs/candidate-brace-abort

spec: syntax-blocks#finding-the-group syntax-inline#algorithm

An unquoted `{` before the first `}` aborts the candidate: it is not a group, the bracket stays text, and the inner `{b}` is not glued to anything. An aborted candidate, like `{}`, is silent; only a candidate that runs to its `}` and fails to parse gets `attr.malformed`.

````tern
[x]{.a {b}}
````

````html
<p>[x]{.a {b}}</p>
````

````diagnostics
````

## attrs/brace-run-linear

spec: syntax-blocks#finding-the-group syntax-inline#algorithm

Thirty thousand `[x]{` in a row, then `}`: each candidate stops at the next `{`, so finding groups stays linear and the line is one paragraph. Every candidate is aborted except the last, which is the empty `{}`; all are silent.

````tern js
'[x]{'.repeat(30000) + '}\n'
````

````json ast
{"type": "root", "children": [{"type": "paragraph"}]}
````

````diagnostics
````

## attrs/empty-after-bracket

spec: syntax-blocks#finding-the-group syntax-inline#span

````tern
[x]{}
````

````html
<p>[x]{}</p>
````

## attrs/key-characters

spec: syntax-blocks#attribute-grammar syntax-blocks#character-classes

## attrs/unquoted-value

spec: syntax-blocks#attribute-grammar



## attrs/key-case-insensitive

spec: syntax-blocks#merging-and-emission syntax-blocks#character-classes

Keys are ASCII-lower-cased, as the browser lower-cases attribute names, so `ID=` and `CLASS=` merge with `#` and `.`, and a repeated key in another case is the same key.

## attrs/reserved-key-tag-unnamed

spec: syntax-blocks#reserved elements#reserved syntax-blocks#r7

`tag=` chooses the element of `:::name`, `::name` and `:name[…]` only. Anywhere else (a bare span, a code span, a heading, a paragraph through its attribute line, an image) it gets `tag.not-allowed` at the key and is dropped, rather than vanishing silently.

````html
<p><img src="a.png" alt="alt"></p>
````

## attrs/reserved-key-cols-elsewhere

spec: syntax-blocks#reserved syntax-blocks#cells syntax-blocks#r7

`cols=` sets the grid of a container, a leaf or an inline element, which all emit `t-cols` and `--t-cols`. On anything else (a paragraph, a bare span) and on a core block such as `:::macros`, which has its own output, it gets `attr.malformed` at the key and is dropped.

````tern
::panel[a]{cols=2}

{#p cols=2}
A paragraph and [a span]{cols=3}.

:::macros{cols=2}
\newcommand{\R}{\mathbb{R}}
:::
````

````html
<div class="panel t-cols" data-t="panel" style="--t-cols:repeat(2,minmax(0,1fr))">a</div>
<p id="p">A paragraph and <span>a span</span>.</p>
````

## attrs/fence-keys-elsewhere

spec: syntax-blocks#merging-and-emission

`lines`, `hl` and `start` are reserved on fences only; on a container they are ordinary attributes.

````tern
:::box{start=3}
Text.
:::
````

````html
<div class="t-block box" data-t="box" start="3">
<p>Text.</p>
</div>
````

## attrs/key-proto

spec: syntax-blocks#merging-and-emission syntax-blocks#character-classes

`__proto__` is a KEY like any other: it is kept as an attribute and emitted, never taken as the object's prototype.

````tern
[x]{__proto__=a}
````

````html
<p><span __proto__="a">x</span></p>
````
