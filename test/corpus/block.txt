# The line algorithm (blocks own their lines, indentation is insignificant, line-start escapes)

Classification order, the "interrupts a paragraph" column (one case per row),
prefix containers and verbatim leaves, lazy continuation, the end of the
note, and the line-start escapes. Quote- and list-specific laziness lives in
quote.txt and list.txt.

## block/leading-whitespace-ignored

spec: syntax-blocks#r2 syntax-blocks#line-algorithm syntax-blocks#columns
options: escaped

Outside lists and footnotes, leading whitespace is ignored when a line is classified: there are no indented code blocks.

````tern
    # Heading
        > quote
\t---
````

````html
<h1 id="heading">Heading</h1>
<blockquote><p>quote</p></blockquote>
<hr>
````

## block/container-body-indented

spec: syntax-blocks#r2 syntax-blocks#line-algorithm
options: schema=none

Container bodies may be indented freely; the indentation means nothing.

````tern
:::box
    # Title
        Indented text.
:::
````

````html
<div class="t-block box" data-t="box"><h1 id="title">Title</h1><p>Indented text.</p></div>
````

## block/fence-dedent-by-opener

spec: syntax-blocks#r2 syntax-blocks#fence

Fence content is dedented by the indentation of its opening fence, and no more.

````tern
  ```
  a
    b
  ```
````

````html
<pre data-t="code"><code>a
  b</code></pre>
````

## block/blank-whitespace-only

spec: syntax-blocks#line-algorithm syntax-blocks#r3 syntax-blocks#paragraph
options: escaped

A line holding only spaces and tabs is blank (row 1), so it ends the paragraph.

````tern
One
 \t
Two
````

````html
<p>One</p>
<p>Two</p>
````

## block/phrasing-tag-continues

spec: syntax-blocks#line-algorithm syntax-blocks#raw-html

A phrasing tag is not row 4, so it continues the paragraph and passes through inline.

````tern

<b>bold</b> continues it
````

````html
<p>Some prose
<b>bold</b> continues it</p>
````

## block/interrupt-table

spec: syntax-blocks#line-algorithm syntax-blocks#tables

Row 7, first form: a `|` line followed by a delimiter row interrupts a paragraph.

````tern
Some prose
| a | b |
|---|---|
| 1 | 2 |
````

````html
<p>Some prose</p>
<table><thead><tr><th>a</th><th>b</th></tr></thead><tbody><tr><td>1</td><td>2</td></tr></tbody></table>
````

## block/delimiter-row-does-not-interrupt

spec: syntax-blocks#line-algorithm syntax-blocks#tables syntax-blocks#paragraph

Row 7, second form: a delimiter row starts a table only at a block start, so inside a paragraph it is text, with a warning.

````tern
Some prose
|---|---|
````

````html
<p>Some prose
|---|---|</p>
````

````diagnostics
2:1 warning table.stray-delimiter
````

## block/interrupt-cell

spec: syntax-blocks#line-algorithm syntax-blocks#cells

## block/interrupt-leaf

spec: syntax-blocks#line-algorithm syntax-blocks#leaf
options: schema=none

Row 12: a line that is a whole leaf interrupts a paragraph.

````tern
Some prose
::box[x]
````

````html
<p>Some prose</p>
<div class="box" data-t="box">x</div>
````

## block/demoted-leaf-continues

spec: syntax-blocks#line-algorithm syntax-blocks#leaf

A leaf interrupts only on a whole-line match; a prose line starting with `::` continues the paragraph. A line that never matched a block row is an ordinary paragraph line and carries its diagnostic wherever it appears, continuation lines included, so `leaf.demoted` fires here.

````tern
Some prose about CSS:
::before and ::after are pseudo-elements.
````

````html
<p>Some prose about CSS:
::before and ::after are pseudo-elements.</p>
````

````diagnostics
2:1 info leaf.demoted
````

spec: syntax-blocks#line-algorithm syntax-blocks#footnote-definition

## block/weak-attribute-line-continues

spec: syntax-blocks#line-algorithm syntax-blocks#attribute-line

Weak or unparsable groups are not row 15, so they continue the paragraph, silently.

````tern
Some prose
{x}
{1, 2}
````

````html
<p>Some prose
{x}
{1, 2}</p>
````

## block/prefix-fail-closes-fence

spec: syntax-blocks#line-algorithm syntax-blocks#fence syntax-blocks#blockquote

Step 2: when a prefix fails, an open verbatim leaf closes as unclosed (no lazy continuation into code), with its diagnostic at the opener.

````tern
> ```
> code
after
````

````html
<blockquote><pre data-t="code"><code>code</code></pre></blockquote>
<p>after</p>
````

````diagnostics
1:3 error block.unclosed-fence
````

## block/prefix-fail-closes-display-math

spec: syntax-blocks#line-algorithm syntax-blocks#display-math syntax-blocks#lists

Step 2 for display math: the list item's prefix fails, so the equation closes as unclosed and `y` starts a paragraph after the list. The error block holds the remainders, without the item's prefix.

````tern
- $$
  x
y
````

````html
<ul><li><div class="t-eq t-error">$$
x</div></li></ul>
<p>y</p>
````

````diagnostics
1:3 error math.unclosed
````

## block/prefix-fail-closes-raw-html

spec: syntax-blocks#line-algorithm syntax-blocks#raw-html syntax-blocks#blockquote

Step 2 for a generic raw block: the quote's prefix fails, which is a parent end, so the block closes with `html.unclosed` at the tag line, at the remainder's column inside the quote. A generic block stays raw HTML (the error block applies only to comment and raw-text blocks), and `inside` holds no Tern syntax, so there is no `html.wrapper`.

````tern
> <div>
> inside
outside
````

````html
<blockquote><div>
inside</blockquote>
<p>outside</p>
````

````diagnostics
1:3 error html.unclosed
````

## block/verbatim-leaf-gets-remainder

spec: syntax-blocks#line-algorithm syntax-blocks#fence syntax-blocks#blockquote

Step 2: when every prefix matches, the remainder goes to the open leaf as content, so `#` inside a quoted fence is code.

````tern
> ```
> # not a heading
> ```
````

````html
<blockquote><pre data-t="code"><code># not a heading</code></pre></blockquote>
````

## block/end-of-note-closes-each

spec: syntax-blocks#line-algorithm syntax-blocks#fence syntax-blocks#closer
options: schema=none

Step 5: at the end of the note every open block is closed, each with its own diagnostic.

````tern
:::box
```js
x
````

````html
<div class="t-block box" data-t="box"><pre data-t="code"><code class="language-js">x</code></pre></div>
````

````diagnostics
1:1 error block.unclosed
2:1 error block.unclosed-fence
````

spec: syntax-inline#line-start-escapes syntax-blocks#fence
