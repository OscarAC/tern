# Containers and closers

Containers (opener grammar, titles, failure modes, reserved verbatim names), closers, the depth limit of the line algorithm, and the first two of "the three most likely mistakes". Names outside the fixture schema (`box`, `idea`, `outer`, `inner`, `sidebar`, `d`) render as `div.t-block NAME`.

## container/unknown-name

spec: syntax-blocks#container elements#output-contract syntax-blocks#r6

A name with no schema entry and no allowlist match becomes `div.t-block NAME`, with its title as a `div.t-title` first child (the second container example).

````tern
:::idea[Key idea]{#k}
Body.
:::
````

````html
<div id="k" class="t-block idea" data-t="idea">
<div class="t-title">Key idea</div>
<p>Body.</p>
</div>
````

## container/schema-theorem

spec: syntax-blocks#container elements#output-contract

The first container example, with the fixture schema: a `<section>` whose title starts with the real-text label.

````tern
:::theorem[Rank–nullity]{#thm-rn .big}
If $V$ is finite-dimensional then …
:::
````

````html
<section id="thm-rn" class="t-block theorem big" data-t="theorem">
<div class="t-title"><span class="t-label">Theorem 1</span> Rank–nullity</div>
<p>If <span class="t-math">V</span> is finite-dimensional then …</p>
</section>
````

## container/opener-spaces-between-parts

spec: syntax-blocks#container

The opener grammar allows spaces between the name, the title and the group (`NAME ws* [title] ws* ATTRS?`); only the name must be glued to the colons.

````tern
:::box [T] {.c}
Text.
:::
````

````html
<div class="t-block box c" data-t="box">
<div class="t-title">T</div>
<p>Text.</p>
</div>
````

## container/title-nested-brackets

spec: syntax-blocks#container

Brackets nest inside a title, so balanced inner brackets do not end it.

````tern

Text.
:::
````

````html
<div class="t-block box" data-t="box">
<div class="t-title">See [this] and f[x]</div>
<p>Text.</p>
</div>
````

## container/title-code-protects-bracket

spec: syntax-blocks#container syntax-inline#algorithm

A code span is an atom, so an unbalanced `]` inside it does not end the title.

````tern
:::box[Use `a]b` here]
Text.
:::
````

````html

<div class="t-title">Use <code>a]b</code> here</div>
<p>Text.</p>
</div>
````

## container/title-nested-unbalanced

````tern
:::box[a [b]
Text.
:::
````

````html

<p class="t-error">[a [b]</p>
````

## container/named-closer-closes-two

spec: syntax-blocks#closer diagnostics#three-mistakes

`:::/outer` closes the nearest `outer`; the `inner` still open inside it is closed too and reported at its own opener.

````tern
:::outer
:::inner
Text.
:::/outer
````

````html
<div class="t-block outer" data-t="outer">
<div class="t-block inner" data-t="inner">
<p>Text.</p>
</div>
</div>
````


## container/closer-mismatch

spec: syntax-blocks#closer

````tern

:::/proof
:::
````

````html
<div class="t-block sidebar" data-t="sidebar">
<p>Text.</p>
<p>:::/proof</p>
</div>
````

````diagnostics
4:1 error block.closer-mismatch "sidebar"
````

````tern
:::/proof
````

## container/closer-name-case

spec: syntax-blocks#closer syntax-blocks#container syntax-blocks#character-classes

Names are case-sensitive: `:::/box` does not close `:::Box`. It is a mismatch, a closer-shaped line that interrupts the paragraph and becomes a paragraph of its own, and `Box` stays open to the end of the note.

````tern
:::Box
Text.
:::/box
````

````html
<div class="t-block Box" data-t="Box">
<p>Text.</p>
<p>:::/box</p>
</div>
````

````diagnostics
3:1 error block.closer-mismatch "Box"
1:1 error block.unclosed ":::/Box"
````

## container/stray-closer-after-paragraph-line


spec: syntax-blocks#container syntax-blocks#line-algorithm

````tern
Text.

:::
````

## container/bad-opener-forms

spec: syntax-blocks#container syntax-blocks#closer

`block.bad-opener` covers `:::` followed by anything other than a NAME, `/NAME` or the end of the line: a bare `/`, a NAME that does not start with a letter, punctuation, and a named closer with text after it. Each line is paragraph text.

````tern
:::/

:::_x

:::!

:::/box extra
````

````html
<p>:::/</p>
<p>:::_x</p>
<p>:::!</p>
<p>:::/box extra</p>
````

````diagnostics
1:1 warning block.bad-opener
3:1 warning block.bad-opener
5:1 warning block.bad-opener
7:1 warning block.bad-opener
````

## container/opener-junk-after-title

## container/depth-64

spec: syntax-blocks#line-algorithm syntax-blocks#container

The 65th nested opener would make the stack deeper than 64, so it is paragraph text inside the 64th container, with `nesting.limit` at it; the 64 closers then close the 64 containers.

````tern js
':::d\n'.repeat(65) + ':::\n'.repeat(64)
````

````diagnostics
65:1 error nesting.limit
````

## container/depth-64-allowed

spec: syntax-blocks#line-algorithm syntax-blocks#container

Exactly 64 nested containers are within the limit.

````tern js
':::d\n'.repeat(64) + 'deep\n' + ':::\n'.repeat(64)
````

````diagnostics
````

## container/depth-counts-quotes

spec: syntax-blocks#line-algorithm

The depth limit counts containers, list items and quotes on one stack: a quote opened inside 64 containers is the 65th level.

````tern js
':::d\n'.repeat(64) + '> q\n' + ':::\n'.repeat(64)
````

````diagnostics
65:1 error nesting.limit
````

## container/depth-counts-footnote-definition

spec: syntax-blocks#line-algorithm syntax-blocks#footnote-definition

Footnote definitions count toward the depth too: inside 63 containers a definition is level 64, so a quote in its body would be the 65th level and is refused at its `>`.

````tern js
'See [^a].\n' + ':::d\n'.repeat(63) + '[^a]: x\n\n  > q\n' + ':::\n'.repeat(63)
````

````diagnostics
67:3 error nesting.limit
````
