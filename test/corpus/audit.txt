# Audit reproductions

Every reproduction from the 2026-10-06 audit of the 0.1 implementation
(`design/audit/findings.json`, tag `v0.1-legacy`) that concerns parsing or
rendering of note source, re-expressed in the new syntax with the output and
diagnostics the documentation requires. Each case's prose names the finding it comes
from. Runtime, editor, CSS and documentation findings are not here: they belong
to test/smoke.js, the editor tests and the docs.

## audit/html-block-after-pre

spec: syntax-blocks#raw-html elements#raw-html-scoping syntax-blocks#r1


## audit/html-style-then-div-wrapper

spec: syntax-blocks#raw-html elements#raw-html-scoping

From html-block-end-regex-leak: the documented pattern (a `<style>` block, then a `<div>` wrapper) no longer swallows the note. The wrapper's body is raw HTML, shown as written, and the heading after it is a heading. The body's first line holds Tern syntax (`*`, `$`), so it gets `html.wrapper` even with no blank line before it; the `<style>` block, a raw-text kind, never does.

````tern
<style>
.box { border: 1px solid; }
</style>

<div class="box">
This paragraph is **parsed**, and so is $x^2$.
</div>

## Second heading

Final paragraph with *emphasis*.
````

````html
<style>
.box { border: 1px solid; }
</style>
<div class="box">
This paragraph is **parsed**, and so is $x^2$.
</div>
<h2 id="second-heading">Second heading</h2>
<p>Final paragraph with <em>emphasis</em>.</p>
````

````diagnostics
6:1 warning html.wrapper
````

## audit/emphasis-unclosed-mixed-openers

spec: syntax-inline#emphasis syntax-inline#algorithm

From exponential-emphasis-hang: the pathological shapes, small. Unclosed mixed-width `*` openers are literal, `**a*` runs resolve by CommonMark's delimiter algorithm, and `_` is never a delimiter. The large versions are in test/perf.js.

````tern
*a **b *a **b *a **b

In Python, *args collects positional arguments and **kwargs collects keyword arguments.

**a***a***a*

_a __b _a __b _a __b
````

````html
<p>*a **b *a **b *a **b</p>
<p>In Python, *args collects positional arguments and **kwargs collects keyword arguments.</p>
<p><strong>a</strong><em>a</em>*<em>a</em></p>
<p>_a __b _a __b _a __b</p>
````

## audit/digit-first-id-unreferenceable

spec: elements#ids syntax-inline#reference syntax-blocks#character-classes
options: schema=none

It is a valid HTML id that is not an IDENT, so it is kept and gets `ref.unreferenceable` (never also `id.invalid`, which is for empty or spaced values), at the first letter of `id=`; `@2024-plan` is plain text.

````tern
:::note{id=2024-plan}
x
:::

see @2024-plan
````

````json ast
{"type": "root", "children": [

  {"type": "paragraph", "children": [{"type": "text", "value": "see @2024-plan"}]}
]}
````

## audit/meta-in-body-is-text

spec: elements#meta-block syntax-inline#raw-inline-html syntax-blocks#raw-html

From rewrite-discards-head-no-metadata-config (also accessibility-gaps, r2-4/rtl-math-mirrored): a `<meta>` in the body was wrapped in `<p>` and there was no way to set lang or dir. Metadata goes in `:::meta`, which emits nothing in the body and fills `root.data.tern.meta`, a plain `{key: string}` object. A `<meta>` tag in the note is escaped text with `html.inline-escaped`: an escaped start tag with a lower-case, non-phrasing name.

````tern
<meta name="description" content="Kernel and image">

:::meta
description: Kernel and image
lang: ar
dir: rtl
:::

# Heading one
````

````json ast
{"type": "root", "data": {"tern": {"meta": {"description": "Kernel and image", "lang": "ar", "dir": "rtl"}}}}
````

````html
<p>&lt;meta name="description" content="Kernel and image"&gt;</p>
<h1 id="heading-one">Heading one</h1>
````

````diagnostics
1:1 info html.inline-escaped
````
