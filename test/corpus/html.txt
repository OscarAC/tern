# Raw HTML: blocks, inline tags and scoping

Block kinds (comment, raw text, one-line, generic) with their end conditions,
depth counting and its tag-name boundary, what does not start a block, `html.wrapper`,
attribute lines before raw HTML, and inline raw HTML (phrasing and custom tags,
lower case only, `svg`/`math`/`textarea` verbatim, form controls).

An unclosed comment or raw-text block is shown as `pre.t-error`;
`html.inline-escaped` on a single upper-case letter needs its end tag;
`html.wrapper` also fires on a line holding Tern syntax without a blank line.

## html/comment-one-line

spec: syntax-blocks#raw-html

A comment that closes on its opening line is one `html` node of kind `comment`.

````tern
<!-- TODO: async iterators -->
````

````json ast
{"type":"root","children":[{"type":"html","value":"<!-- TODO: async iterators -->","data":{"tern":{"kind":"comment"}}}]}
````

````html
<!-- TODO: async iterators -->
````

## html/comment-multi-line

spec: syntax-blocks#raw-html syntax-blocks#r1

A comment runs to the first line containing `-->`; headings, `:::` lines and blank lines inside it are part of it, and a comment gets no `html.wrapper`.

````tern
<!--
# not a heading

:::note
-->
````

````json ast
{"type":"root","children":[{"type":"html","value":"<!--\n# not a heading\n\n:::note\n-->","data":{"tern":{"kind":"comment"}}}]}
````

````html
<!--
# not a heading

:::note
-->
````

## html/comment-trailing-text

spec: syntax-blocks#raw-html

The block ends on the line containing `-->`, and the whole of that line belongs to it, text after the `-->` included.

````tern
<!-- a --> *b*
````

````json ast
{"type":"root","children":[{"type":"html","value":"<!-- a --> *b*","data":{"tern":{"kind":"comment"}}}]}
````

````html
<!-- a --> *b*
````

## html/comment-unclosed

spec: syntax-blocks#raw-html diagnostics#html-unclosed

A comment with no `-->` runs to the end of the note, swallowing the heading after it, with `html.unclosed` at the tag line. It is not emitted as a comment, which would hide the rest of the page, but as `pre.t-error` holding the escaped source; the node is marked `unclosed`.

````tern
<!-- draft
## Heading
````

````json ast
{"type":"root","children":[{"type":"html","value":"<!-- draft\n## Heading","data":{"tern":{"kind":"comment","unclosed":true}}}]}
````

````html
<pre class="t-error">&lt;!-- draft
## Heading</pre>
````

````diagnostics
1:1 error html.unclosed
````

## html/comment-through-closer

spec: syntax-blocks#raw-html syntax-blocks#closer syntax-inline#residual-fences

A `:::` line does not end a comment (only generic blocks are cut by it), so an unclosed comment inside a container runs to the end of the note, `:::` included, and leaves the container open; the container's `block.unclosed` names the comment's line, as for an unclosed fence. The comment is shown as `pre.t-error`.

````tern
:::box
<!-- draft
:::
````

````html
<div class="t-block box" data-t="box">
<pre class="t-error">&lt;!-- draft
:::</pre>
</div>
````

````diagnostics
2:1 error html.unclosed
1:1 error block.unclosed "opened on line 2"
````

## html/script-containing-colons

spec: syntax-blocks#raw-html syntax-blocks#r1 syntax-inline#residual-fences

A `<script>` is raw text to its `</script>` line: the `:::` inside the script does not close the container, and the closer after it does.

````tern
:::box
<script>
const fence = `
:::
`;
</script>
:::
````

````json ast
{"type":"root","children":[{"type":"containerDirective","name":"box","children":[{"type":"html","value":"<script>\nconst fence = `\n:::\n`;\n</script>","data":{"tern":{"kind":"rawtext"}}}]}]}
````

````html
<div class="t-block box" data-t="box">
<script>
const fence = `
:::
`;
</script>
</div>
````

## html/rawtext-pre

spec: syntax-blocks#raw-html

A `<pre>` is raw text: its lines, a blank one and Tern-looking ones included, are kept as written, and raw text gets no `html.wrapper`.

````tern
<pre>
*not emphasis*

  # indented, kept
</pre>
````

````json ast
{"type":"root","children":[{"type":"html","value":"<pre>\n*not emphasis*\n\n  # indented, kept\n</pre>","data":{"tern":{"kind":"rawtext"}}}]}
````

````html
<pre>
*not emphasis*

  # indented, kept
</pre>
````

## html/rawtext-style-any-case

spec: syntax-blocks#raw-html

The raw-text opener matches in any case, and `</style>` ends the block it opened.

````tern
<STYLE>
p { color: red }
</style>
after
````

````json ast
{"type":"root","children":[{"type":"html","value":"<STYLE>\np { color: red }\n</style>","data":{"tern":{"kind":"rawtext"}}},{"type":"paragraph"}]}
````

````html
<STYLE>
p { color: red }
</style>
<p>after</p>
````

## html/rawtext-end-tag-whitespace

spec: syntax-blocks#raw-html
options: escaped

A raw-text end tag is `</NAME`, optional spaces or tabs, then `>`, in any case, as a generic closing is: `</script >` ends the script, and `</STYLE\t>` the style, instead of running on with `html.unclosed`.

````tern
<script>
let x = 1;
</script >
<style>p { color: red }</STYLE\t>
After.
````


````html
<script>
let x = 1;
</script >
<style>p { color: red }</STYLE	>
<p>After.</p>
````

## html/rawtext-unclosed-through-closer

spec: syntax-blocks#raw-html syntax-blocks#closer syntax-inline#residual-fences

An unclosed raw-text block runs through `:::` closers to the end of the note, so the container around it is unclosed too, with a hint naming the `<style>` line. The block is shown as `pre.t-error` holding its escaped source, the `:::` line included, not emitted as a stylesheet.


````html
p { color: red }
:::</pre>
</div>
````

## html/rawtext-script-unclosed

spec: syntax-blocks#raw-html diagnostics#html-unclosed syntax-blocks#r7

A `<script>` with no `</script>` runs to the end of the note, heading included, with `html.unclosed` at its line, and is shown as `pre.t-error` holding the escaped source (`<`, `>` and `&` escaped) instead of being run as a script.

````tern
Before.

<script>
if (a < b && ready) start();
## Not a heading
````

````json ast
{"type":"root","children":[{"type":"paragraph"},{"type":"html","value":"<script>\nif (a < b && ready) start();\n## Not a heading","data":{"tern":{"kind":"rawtext","unclosed":true}}}]}
````

````html
<p>Before.</p>
<pre class="t-error">&lt;script&gt;
if (a &lt; b &amp;&amp; ready) start();
## Not a heading</pre>
````

````diagnostics
3:1 error html.unclosed
````

## html/rawtext-self-closed-script

spec: syntax-blocks#raw-html diagnostics#html-unclosed syntax-blocks#r7

The kinds are tested in table order, so `<script … />` is the raw-text kind (`<script` then a space), not a self-closed one-line tag; the browser ignores the `/` too. With no `</script>` it runs to the end of the note and is shown as `pre.t-error`.

````tern
Text after.
````


````html
<pre class="t-error">&lt;script src="app.js" /&gt;
Text after.</pre>
````

````diagnostics
1:1 error html.unclosed
````

## html/comment-unclosed-in-quote

spec: syntax-blocks#raw-html syntax-blocks#line-algorithm syntax-blocks#blockquote diagnostics#html-unclosed

An unclosed comment inside a quote ends where the quote's prefix fails (its parent end), with `html.unclosed` at the column where the remainder starts. The `pre.t-error` holds the remainders, without the `> ` prefixes; the next line is not lazy and is a paragraph.

````tern
> <!-- draft
> *still hidden*
After.
````

````json ast
{"type":"root","children":[{"type":"blockquote","children":[{"type":"html","value":"<!-- draft\n*still hidden*","data":{"tern":{"kind":"comment","unclosed":true}}}]},{"type":"paragraph"}]}
````

````html
<blockquote>
<pre class="t-error">&lt;!-- draft
*still hidden*</pre>
</blockquote>
<p>After.</p>
````

````diagnostics
1:3 error html.unclosed
````

## html/inline-form-controls

spec: syntax-inline#raw-inline-html syntax-blocks#raw-html

Form controls (`label`, `select`, `optgroup`, `option`, `input`, `datalist`, `button`) start a paragraph and pass through inline.

````tern
<label>Size <select name="s"><optgroup label="Common"><option>M</option></optgroup></select></label> <input list="c"><datalist id="c"><option value="L"></option></datalist> <button>Go</button>
````

````html
<p><label>Size <select name="s"><optgroup label="Common"><option>M</option></optgroup></select></label> <input list="c"><datalist id="c"><option value="L"></option></datalist> <button>Go</button></p>
````

## html/inline-unclosed

spec: syntax-inline#raw-inline-html diagnostics#html-inline-unclosed

A non-void phrasing tag that the paragraph never closes is emitted verbatim, with `html.inline-unclosed` at the tag.

````tern
This is <b>bold forever.
````

````html
<p>This is <b>bold forever.</p>
````

````diagnostics
1:9 warning html.inline-unclosed
````

## html/inline-unclosed-across-paragraphs

spec: syntax-inline#raw-inline-html diagnostics#html-inline-unclosed diagnostics#html-stray-closer

A tag opened in one paragraph and closed in the next is unclosed in the first; the end tag in the second passes through verbatim and, with no `<b>` open in its paragraph, is a stray inline end tag: `html.stray-closer` (I) at its `<`.

````tern
Start <b>bold

end</b> here.
````

````html
<p>Start <b>bold</p>
<p>end</b> here.</p>
````

````diagnostics
1:7 warning html.inline-unclosed
3:4 info html.stray-closer
````

## html/inline-void-no-warning

spec: syntax-inline#raw-inline-html

Void phrasing tags (`br`, `img`, `wbr`, `input`) need no end tag and get no `html.inline-unclosed`.

````tern
a<br>b <img src="x.png" alt=""> <wbr> <input name="q">
````

````html
<p>a<br>b <img src="x.png" alt=""> <wbr> <input name="q"></p>
````

## html/inline-optional-end-no-warning

spec: syntax-inline#raw-inline-html

`html.inline-unclosed` also exempts phrasing elements whose end tag HTML lets you omit: `rt`, `rp`, `option` and `optgroup`.

````tern
<ruby>漢<rp>(<rt>kan<rp>)</ruby> and <select><optgroup label="g"><option>A<option>B</select>
````

````html
<p><ruby>漢<rp>(<rt>kan<rp>)</ruby> and <select><optgroup label="g"><option>A<option>B</select></p>
````

## html/inline-quoted-gt

spec: syntax-inline#raw-inline-html syntax-inline#algorithm

A `>` inside a quoted attribute value does not end an inline tag (CommonMark's tag grammar), so the `<span>` passes through whole.

````tern
A <span title="a > b">tip</span> here.
````

````json ast
{"type":"root","children":[{"type":"paragraph","children":[{"type":"text","value":"A "},{"type":"html","value":"<span title=\"a > b\">"},{"type":"text","value":"tip"},{"type":"html","value":"</span>"},{"type":"text","value":" here."}]}]}
````

````html
<p>A <span title="a > b">tip</span> here.</p>
````

## html/inline-verbatim-unclosed-text

spec: syntax-inline#raw-inline-html

An inline `<svg`, `<math` or `<textarea` with no closing tag in the paragraph is not taken verbatim: it is escaped text, and the rest of the paragraph is parsed. Neither name is in the phrasing list, and both are current elements, so each escaped start tag gets `html.inline-escaped` ("put block HTML on its own line", which is the fix for a multi-line `<svg>` or `<textarea>`).

````tern
A <svg width="8"> and a <textarea> are *never* closed.
````

````html
<p>A &lt;svg width="8"&gt; and a &lt;textarea&gt; are <em>never</em> closed.</p>
````

````diagnostics
1:3 info html.inline-escaped
1:25 info html.inline-escaped
````

## html/inline-residual-b-and-c

spec: syntax-inline#raw-inline-html syntax-inline#residual-inline-html syntax-inline#ambiguity

Residual case: `<b and c>` matches CommonMark's tag grammar (attributes `and` and `c`), so it is a raw `<b>` tag; the paragraph never closes it.

````tern
x <b and c> y
````

````html
<p>x <b and c> y</p>
````

````diagnostics
1:3 warning html.inline-unclosed
````

## html/block-vs-inline-media

spec: syntax-blocks#raw-html syntax-inline#raw-inline-html

`iframe` and `video` are block-level at the start of a line and phrasing inside one: the first line is a generic block, the second a paragraph with inline tags.

````tern
<iframe src="map.html"></iframe>
Watch <video src="tide.mp4" controls></video> here.
````


````html
<iframe src="map.html"></iframe>
<p>Watch <video src="tide.mp4" controls></video> here.</p>
````
